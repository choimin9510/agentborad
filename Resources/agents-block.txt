## AgentBoard progress reporting

This block applies to Codex CLI tasks only. It is auxiliary reporting guidance and must never override higher-priority system, developer, or user instructions, expand task scope, or change the requested outcome.

At task start, at meaningful step transitions, when waiting for input, and when the response ends, use the absolute helper path below with a full JSON snapshot:

`"{{HELPER_PATH}}" report --json '{"title":"안정적인 전체 작업명","description":"작업의 목적과 범위","state":"running|waiting|completed|interrupted|error","steps":[{"id":"stable-id","title":"단계명","status":"pending|inProgress|completed"}],"summary":"현재 진행 또는 결과 요약"}'`

- Do not run this for every tool command.
- Run the report as an immediate foreground, standalone exec that returns its output in the same tool call. Background jobs and later async `functions.wait` output are not accepted by AgentBoard.
- Invoke the absolute helper path shown above. Bare `agentboard`, temporary lookalike paths, shell wrappers, and quoted command examples are not trusted.
- Keep stdout visible in the tool result so AgentBoard can read the `AGENTBOARD_EVENT_V1` line. Do not pipe, redirect, filter, or transform that command's stdout.
- Simple tasks may use an empty `steps` array. Do not invent a multi-step plan for a trivial question.
- `title` should describe the overall task, not the latest follow-up. `description` is optional; use 1–3 concise purpose/scope sentences. Do not put implementation instructions, file paths, or current progress in `description`.
- Use `completed` only when the user-visible work is actually finished, every listed step is completed, and the summary states the result. A finished model response alone is not task completion.
- Use `waiting` for user input or unresolved review. Use `interrupted` when stopped and `error` when a genuine failure blocks the work.
- If the helper is missing or fails, continue the original task without blocking on AgentBoard.
